# Gradle wrapper provenance — M0-R2

The complete official wrapper is now checked in:

- `gradlew` (POSIX shell launcher)
- `gradlew.bat` (Windows launcher)
- `gradle/wrapper/gradle-wrapper.jar`
- `gradle/wrapper/gradle-wrapper.properties`

## Version and source

| Item | Value |
| --- | --- |
| Gradle version | `9.2.1` |
| Distribution URL | `https://services.gradle.org/distributions/gradle-9.2.1-bin.zip` |
| Distribution SHA-256 | `72f44c9f8ebcb1af43838f45ee5c4aa9c5444898b3468ab3f4af7b6076c5bc3f` |
| Wrapper JAR SHA-256 (this repository) | `423cb469ccc0ecc31f0e4e1c309976198ccb734cdcbb7029d4bda0f18f57e8d9` |
| Generation command | `gradle wrapper --gradle-version 9.2.1 --distribution-type bin` |
| Generation host | Windows 11 amd64, Eclipse Temurin JDK `25.0.3+9-LTS` |

The Gradle distribution was downloaded from the official `services.gradle.org`
redirect and checked against the official SHA-256 checksum before extraction.
The wrapper was generated by that verified Gradle installation. The
`distributionSha256Sum` property now makes `gradlew` verify the downloaded
distribution on a clean machine.

The generated wrapper JAR has a different hash from the wrapper JAR in the
official NeoForge MDK template. This repository's JAR was generated by the
checksum-verified Gradle 9.2.1 installation above; that is its provenance. Do
not replace it with a third-party JAR.

The wrapper distribution was also seeded into the local wrapper cache so the
offline authoring host could execute it before its first network download.
That cache is outside the source package; a clean checkout downloads and
verifies the distribution using `distributionSha256Sum`.
